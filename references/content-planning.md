# 内容策划与确认

每个新选题在推荐风格之前读取。用户提供主题即可开始：导演负责提出内容，不要求用户先写脚本。本指南适用于全部风格；不预设 3D、无口播、双语、特定音乐或固定高潮时间。

## 1. 从主题提出具体方案

先提取用户已说明的受众、目的、内容、禁区、时长、音乐、画幅和输出要求，区分“用户已定”“建议待确认”“事实待核实”。默认中文、普通观众、16:9；其他项提出适合主题的建议，不暗中定稿。

只给主题时，先做足以支持选题角度的研究，给出一套推荐内容方案，必要时附一个有实质差异的备选角度。主题存在歧义时先澄清对象，例如“Agent”指 AI Agent 还是软件代理。不要先展示风格、生成场景或写动画代码。

内容策划单必须覆盖：

| 项目 | 导演主动提出 | 与用户明确 |
|---|---|---|
| 主题与一句话定位 | 给谁看、看完能回答什么 | 目标与受众；宣传、入门或机制讲解 |
| 钩子与问题 | 具体场景、经核实事实或反直觉现象；明确悬念 | 开头切入、语气及最终要回答的问题 |
| 核心拆解 | 比喻、过程、两个关键词、名称拆解或因果链 | 采用哪种解释路径；避免牵强拆字 |
| 主角/贯穿对象 | 可见物件、真实界面、标志、文字或操作 | 对象是否贴题，能否获取并合规使用 |
| 中段 | 2–4 个知识节点、对应具体例子和必要边界 | 必须讲/不讲的内容，深度与重点 |
| 第二次揭晓 | 有意义的规模、应用或结果；也可不设 | 是否需要，不能为凑爆点编数字 |
| 结尾 | 回答开头；一句带走的话、意义或行动 | 核心态度、关键词/锚词，避免空泛拔高 |
| 节奏与声音 | 建议时长、音乐驱动或内容驱动、旁白/原声/字幕 | 时长上限、BGM 来源、是否用整曲、音乐与内容冲突时的优先级 |
| 字幕与交付 | 中文/双语，画幅，HTML/MP4，目录 | 阅读负担、成片及无字幕版等需求 |

锚词可选，不是每片必须有。使用时说明它如何从开篇困惑演化为结尾的新理解，避免只当大标题。核心概念的出现时刻依据内容和音乐确定。

## 2. 查事实，再写成片文案

- 年份、人名、数字、引文、产品能力等可核实断言优先查官网、官方博客、年度报告、官方文档/API或原始论文。检索摘要不是完整依据；打开能支持该断言的页面。主题存在争议时标明范围与分歧，不用单方宣传推出普遍结论。
- 真实案例能说明机制时优先采用，记录真实项目、提交、原帖或界面的出处。没有取得的材料不得用仿制画面冒充；示意、推演、简化动画明确标记。
- 动态数字记录日期、统计口径、单位；一手材料的引文保留上下文。事实来源、画面素材来源和授权状态分开记录。
- 拿不准的说法先删去或标为待核实，不写进定稿。联网/来源不可用时说明缺口，继续无依赖的策划；不声称已经核实。
- 重点检查事实与逻辑：是否以偏概全、误把相关性当因果、类比超出适用范围、钩子未回答。避免无依据的“全部、唯一、第一、最”等绝对化表述；有清晰范围和证据的比较不机械禁字。已有口播中的疑点单列，与用户明确处理，不擅改原话。

`FACT_CHECK.md` 随策划建立并持续更新：

| 编号/片中位置 | 拟用写法 | 依据与适用范围 | 来源链接及日期 | 素材/授权状态 | 核实状态 |
|---|---|---|---|---|---|

同一断言的画面、字幕和数字必须一致。策划阶段的位置可用段落 ID，时间轴稳定后补时间码。没有逐条验证的项目不标“通过”。

## 3. 分批明确，而不是让用户填表

先展示简明的推荐方案，再用原生问题工具问关键缺项。每轮通常 1–3 个相关问题，提供具体推荐答案，并允许用户自由修改。不要把上表十项同时变成十个问题，也不要只问“有什么要求”。

推荐节奏（已明确的项跳过）：
1. 先明确受众、目标、时长与表达方式；例如“面向完全不懂的人，用约60秒字幕动画解释它能解决什么问题”。
2. 据此呈现钩子、核心拆解、例子、结尾，确认是否保留或替换。音乐/字幕等尚缺项随同一轮处理；无需为每句话单独审批。
3. 将所有决定汇成完整 `CONTENT_BRIEF.md`，向用户展示精简内容版与分段走向，明确请其确认整套方案。用户已针对这个完整版本说“通过”即可进入风格阶段，不重复确认。

使用 functions.request_user_input_async（可用时），仅在 Plan 模式可用时用 request_user_input；工具不可用则普通回复提问。待答期间可研究事实、核查素材、整理草稿，不进入风格推荐或依赖未定内容的制作。时间流逝、预选项、对某一句的赞许不等于整套内容获批。

用户说“你决定/直接做/按推荐来”等时，按具体授权范围处理：授权所有内容即可将推荐方案记录为定稿并进入风格；只授权音乐不代表授权全篇。已给完整脚本或明确各字段时只补实质缺口，不重复访谈；主题改变或用户要求改动已获批核心叙事时，只重新明确受影响部分。

## 4. 把内容组织成故事

采用可伸缩的叙事骨架，不机械凑段落：

1. **具体钩子**：尽早出现可识别对象、真实场景或事实，让观众知道与自己有什么关系；提出可回答的问题。避免空泛抽象开场与责问观众的套路，用户指定开头除外。
2. **核心揭晓**：用经确认的比喻或拆解给出理解支架。复杂术语可在此之后出现，首次出现用大白话解释。
3. **逐项解释**：每个节点先展示可观察的动作与结果，再说明机制。人物与历史只有在能解释机制或意义时才加入，不为套模板强塞。
4. **可选第二揭晓**：从原理转向规模、现实应用或后果，配有来源的具体案例。短片可合并或省略；若采用双爆点方案，最多两次且主次分明。
5. **回答与结尾**：明确回答开头的问题，再用事实支撑意义。锚词可在此重新诠释；不把情绪口号当解释。

一屏一个意思，中文通常不超过25字、停留约3–5秒；按语言、长度、镜头动作及观众调整，不能机械规定全片30–35句。60秒片应在阅读预算内删减信息；10秒片只讲一个点，不套17秒高潮。双语仅在用户选择后加入，翻译不新增断言。

先写风格无关的 `STORYBOARD.md`，风格选定后补充材质、构图与具体转场。每行注明：

| 段落/作用 | 时间码或暂定占比 | 画面对象与解释动作 | 衔接方式 | 中文字幕 | 英文字幕（可选） | 音乐/音效提示 | 事实编号 |
|---|---|---|---|---|---|---|---|

画面先说明变化、原因与结果，优先让同一对象贯穿；不把“粒子炸开”“镜头推进”等装饰当内容。是否一镜到底、何种材质与字体跟随所选风格，不在内容阶段锁定 three.js 或特定参数。

## 5. 音乐与时间轴：先明确约束，再测量

- 询问“音乐决定片长”还是“内容/平台上限决定片长”。未指定时给建议；不因提供模板就默认整首音乐、17秒或1:33.57。用户固定时长与整曲长度不一致时，明确裁剪/淡出或调整时长的选择。
- 没有音频文件时，仍可完成内容确认和暂定节奏，但节拍标“待测”。用户只提供歌名不能视为已取得音频或使用权；不要冒用其他作品音乐。实际卡点依赖文件到位，不能用静音样片宣称卡点通过。
- 取得音频后用可用工具测量时长、波形/能量并结合听辨确认换气与重拍。ffmpeg可辅助分析，不会自动保证选中了叙事所需重拍。
- 已约定高潮在17秒时执行该要求；若真实音乐强拍与之冲突，列明偏差并让用户选择固定画面时间或跟随音乐，不擅改已锁定卡点。
- 固定帧率下零基帧号 `n = round(t × fps)`，实际呈现时间 `n / fps`；写明帧率、索引规则、误差。17.048秒在30fps下对应零基511帧（17.0333秒），不是所有音乐的通用值。
- 收暗、短暂静止、揭晓、解释小字、阅读停留构成一种可选高潮设计。约3帧静止、冲击音/钟声、辉光等仅在内容方案及风格适合时采用；全片不要反复用同一种爆发。
- 音效数量、BGM电平和混音目标按时长、旁白及平台调整。-8dB音乐增益、-16LUFS/-1dBTP可作方案起点，不是测量结论；无实际音轨分析不宣称达标。

## 6. 交接、修改与验收

内容确认时 `CONTENT_BRIEF.md` 记录：主题/观众/一句话目标、钩子与问题、核心拆解、贯穿对象、中段与边界、可选爆点、结尾、时长与音乐策略、字幕/声音/画幅/交付、未解决依赖、用户原话和版本。给用户的确认摘要应能独立看懂，不仅给文件路径。

风格选择只改变表达方法；若风格需要实质更改已确认内容，先说明差异。样片沿用主流程约20秒，覆盖机制解释与转场；本模板里的10秒720p不是全局要求。用户当次明确要求10秒或特定规格时遵从，并说明它实际能检验的内容。

交付随任务包含内容策划单、分镜、事实清单、HTML及必要本地依赖；请求MP4时才进入视频渲染，并按已确认需求交付有字幕/无字幕版本、SRT和相关源文件。技术栈、字体和渲染方式遵循所选风格及运行环境，不强制全风格使用3D、四段并行或某个浏览器驱动。字体须检查授权与中文字形覆盖；没有工具证据不能声称已逐字符验证实际字体。

验收时核对内容方案、字幕与导出字幕一致，钩子有回答，事实有出处，时间和阅读预算成立。请求成片导出时检查抽帧、连续播放、高潮/分段接缝、解码/时长/帧数及音轨；帧差尖峰只是复查线索，不直接判定闪帧。画面应可按帧号或绝对时间稳定重现；同一输出文件避免并发写入。具体动效和播放器检查见 motion-delivery.md。

修改时保留有效确认和先前明确的改动，只改受影响的方案/段落并对比差异。用户夸某处不代表要求修改；存在会改变含义的歧义先问清楚。局部重渲仅在时间轴和依赖允许时采用，不保证所有修改都能不重出全片。
